# Wild Count — ゲーム中ドーパミン演出計画

作成日: 2026-07-20

状態: 計画

関連: `docs/design-polish-plan.md` / `docs/ui-mock.md` / `docs/ui-redesign.md` / `docs/backlog.md`

## 1. 背景

既存実装には、宣言 slam、手番到来、ROUND、特殊能力、COYOTE、カード公開、結果差、紙吹雪などの CSS 演出がある。一方、強い報酬演出は宣言確定時と結果画面に寄っており、数字を選ぶ時間や宣言が連続する時間には、盛り上がりが蓄積している感覚がまだ弱い。

本計画では、ゲーム中に次の短いループを繰り返す。

```text
自分の手番が来る
  → 数字を操作して期待が高まる
  → 宣言が卓へ着弾する
  → 連続宣言で卓の熱量が上がる
  → COYOTE で熱量を解放する
  → 公開・判定・勝敗で最大の反応を返す
```

## 2. ゴール

- 結果を待たなくても、毎手番の操作と宣言確定に気持ちよい反応がある
- 宣言が続くほど、卓全体の緊張と演出強度が段階的に高まる
- 大幅宣言、残り時間ぎりぎり、特殊札逆転など、プレイ内容に応じて見せ場が変わる
- COYOTE から結果確定までを、このゲーム最大の解放ポイントにする
- ローカルとオンラインで、同じ公開情報から同じ演出ランクを再現する

## 3. 非ゴール・ガードレール

- 勝率、カード、手番順、制限時間などゲームルールは変更しない
- 手札や実際の合計など、非公開情報を推測できる演出は行わない
- ランダム報酬、ログイン誘導、課金誘導、損失回避を使った継続強制は導入しない
- 演出のために操作確定や通信を待たせない。長押しは任意で、タップなら即時確定できる
- `prefers-reduced-motion`、SFX ミュート、触覚 OFF を尊重する
- 既存の Coyote / Extra / Bid cut-in を同時表示させず、優先順位で衝突を防ぐ

## 4. コア仕様

### 4.1 HEAT — 卓の盛り上がり

ラウンド内でチャレンジされず宣言が続いた回数を、表示専用の `heatLevel` に変換する。ゲーム状態や勝敗には影響しない。

| HEAT | 仮条件 | 表示 | 音・動き |
|------|--------|------|----------|
| WARM UP | 1〜2 宣言 | 通常の gold | 軽い着弾音、既存ポップ |
| HEATING | 3〜5 宣言 | gold の発光増加 | 弱い背景パルス、音程上昇 |
| DANGER | 6〜8 宣言 | gold → amber/red | 周辺パルス、火花、低い鼓動 |
| WILD | 9 宣言以上 | 専用 WILD 状態 | 強い着弾、短い画面シェイク、音楽レイヤー候補 |

ルール:

- ラウンド開始時に 0、各宣言確定で +1、COYOTE 発動で固定して公開演出へ引き継ぐ
- 閾値は実プレイで調整し、人数差が大きければ「宣言数 ÷ 生存人数」の正規化を検討する
- HEAT は全クライアントで再現可能な宣言履歴または同期済みカウンターから算出する
- 常時ゲージを増やさず、中央宣言表示、卓の縁、`RALLY` 表示の強度として見せる

### 4.2 RALLY — 連続宣言フィードバック

- 2 回目以降の宣言に `RALLY ×2`, `×3`…を短時間表示する
- 宣言者から次の手番プレイヤーへ光の軌跡を送る
- 数が増えるほど着弾音の音程、リング、粒子密度を段階的に上げる
- COYOTE、ラウンド終了、再接続後の別ラウンドでリセットする
- ゲーム上の倍率や報酬と誤認させないよう「演出」「連続宣言」であることをヘルプに記す

### 4.3 RAISE ランク — 強気な宣言を即時に褒める

既存の `raise intensity` と `BidDeclareCutIn` を正本として拡張し、二重判定を作らない。

| 直前との差 | ランク | 表示案 |
|------------|--------|--------|
| +1〜2 | normal | 既存ポップのみ |
| +3〜5 | nice | `NICE RAISE` |
| +6〜9 | big | `BIG JUMP +N` |
| +10 以上 | wild | `WILD CALL +N` |
| 前回の 2 倍以上 | modifier | 上記に専用リングを追加 |

- 初手は差分ではなく絶対値で分類する
- ラベルは短時間だけ表示し、イベントログには追加しない
- 閾値と文言は定数化し、テスト可能にする

### 4.4 入力中フィードバック

- `+ / -`: 押下スケール、数字の上下スライド、短いクリック音
- 連打・長押し: 変化速度に合わせ、クリック音のピッチと数字の移動量を上げる
- 宣言ボタン: pointer down 中だけ 150〜300ms のチャージ表現。pointer up / keyboard activate で即確定
- 宣言確定: 操作部から中央表示へ数字を射出し、中央でリングと粒子を出す
- 無効操作: 派手な報酬音を出さず、小さな境界フィードバックだけ返す

アクセシビリティ:

- キーボード、スクリーンリーダー経由でも操作結果は同じにする
- reduced motion 時は移動・シェイクを省き、色と短いフェードへ置換する
- チャージ表現を見なくても、宣言値と確定状態を判別できるようにする

### 4.5 自分の手番と時間

- 手番到来時、該当席から操作エリアへ光を 1 回だけ流す
- SFX ON 時は短い通知音、触覚 ON 時は短振動 1 回
- 残り時間が警告域に入ったときだけ、時計の視覚パルスと控えめな心音を開始する
- 秒ごとのシェイクや連続振動は行わない
- バックグラウンドタブ復帰時に古い手番演出をまとめて再生しない

### 4.6 特殊能力

各能力に「色・シルエット・短い音」を割り当て、通常宣言と区別する。既存 `ExtraActionCutIn` を拡張し、新しい全画面レイヤーは増やさない。

- SAME: 二重エコー
- CHANGE: 数字の分解・再構成
- REVERSE: 卓を一周する逆回転ライン
- SHOT: 対象席への直線インパクト
- DRAW: カードが山から対象席へ飛ぶ
- DOUBLE: `×2` が中央へ叩き込まれる

同時に宣言を伴う場合は、特殊能力 cut-in → 宣言着弾の順で短く連結する。

### 4.7 COYOTE 解放シーケンス

```text
COYOTE 発動
  → 操作音と背景レイヤーを停止（約 250ms）
  → 既存 CoyoteCutIn
  → カードを順次公開し、1枚ごとに打音
  → 特殊札の計算効果を短く強調
  → 最終合計の直前で約 500ms ホールド
  → 合計数字を slam
  → 宣言との差を表示
  → 勝敗・ライフ変化を解放
```

- 待ち時間は演出設定で短縮・スキップ可能にする
- オンラインでは結果データ受信を先に完了し、表示だけを順次進める
- タブ非表示、再接続、演出スキップ時は最終状態へ安全に収束させる
- 連打、二重マウント、view 更新でシーケンスを再実行しない

### 4.8 プレイ内容によるレア演出

乱数ではなく、公開されたプレイ結果を条件にする。

| 条件 | 仮ラベル | 演出 |
|------|----------|------|
| 宣言値と合計が一致 | `PERFECT` | gold/white の専用 slam |
| 差が 1 | `CLUTCH` | 一瞬の停止後に判定 |
| 特殊札で通常和から勝敗逆転 | `WILD REVERSAL` | 特殊札色から勝敗色へ反転 |
| 残り 1 秒以内の有効宣言 | `LAST SECOND` | 時計破裂エフェクト |
| ライフ 1 で生存 | `SURVIVED` | ハート再点灯 |
| WILD HEAT で決着 | `MAX HEAT` | 最大密度の解放演出 |

既存 `resultDrama.ts` の exact / clutch / clear / blowout を利用し、結果分類を重複させない。

## 5. SFX・触覚仕様

### 5.1 設定

- 演出プリセット: `ひかえめ` / `WILD`
- 効果音: ON/OFF、音量
- 触覚: OFF/ON。初期値は OFF
- 設定は端末の localStorage に保存し、ゲーム中にも変更可能
- ブラウザの autoplay 制限に対応し、最初のユーザー操作後に音声を初期化する

### 5.2 音の優先順位

1. COYOTE / 勝敗
2. 特殊能力
3. 宣言着弾 / 自分の手番
4. 入力クリック / 背景心音

上位音が鳴るときは下位音を duck または停止する。短時間に複数イベントを受けても音量が積み上がらないよう、同系統 SFX にクールダウンを設ける。

### 5.3 触覚パターン案

| イベント | パターン |
|----------|----------|
| 自分の手番 | 短振動 1 回 |
| 宣言確定 | ごく短い 1 回 |
| WILD CALL | 短振動 2 回 |
| COYOTE | 強・間・強 |
| ライフ喪失 | 中程度 2 回 |

`navigator.vibrate` 非対応端末では何もしない。触覚の有無で情報量に差を作らない。

## 6. 演出の優先順位

同時発火時は次の順で表示する。

```text
COYOTE / 結果
  > 特殊能力
  > WILD CALL / BIG JUMP
  > 手番到来
  > RALLY / 入力フィードバック
```

- 全画面 cut-in は 1 つだけ
- 低優先度演出は待たせず、省略してよい
- ゲーム操作、タイマー、WebSocket 処理は演出キューから独立させる

## 7. 実装スライス

### D0 — 計測と共通モデル

1. 現在の宣言 FX、結果 FX、タイマーイベントの発火箇所を一覧化
2. `heatLevel`、`rallyCount`、`raiseTier` を純粋関数として定義
3. ローカル / オンライン共通の演出イベント型を定義
4. 二重発火防止用の event identity を決める

完了条件:

- 同じ公開ゲーム状態から同じ演出分類が得られる
- 閾値の単体テストがある
- ルールエンジンに演出専用状態を混入させていない

### D1 — 宣言ループ

1. HEAT の段階表現
2. RALLY 表示と席間の光
3. 既存 raise intensity を NICE / BIG / WILD に拡張
4. 入力クリック、任意チャージ、中央への着弾を接続
5. reduced-motion とモバイル負荷を確認

完了条件:

- 通常宣言は短く、大幅宣言だけ強く見える
- 宣言操作をブロックせず、連打でも表示が破綻しない
- 3人 / 4人 / 10人モックで HEAT の上がり方を確認できる

### D2 — SFX

1. 音声マネージャー、カテゴリ、音量、ミュートを実装
2. 入力、宣言、手番、特殊能力、COYOTE、公開、勝敗へ接続
3. HEAT / RAISE に応じたピッチまたは音レイヤーを追加
4. autoplay、タブ復帰、連続イベントを検証

完了条件:

- SFX OFF では音声リソースを再生しない
- 音だけで非公開情報を伝えない
- 同時イベントでクリップや過大音量が発生しない

### D3 — COYOTE とレア決着

1. 無音、公開、ホールド、合計 slam のタイミングを統合
2. PERFECT / CLUTCH / WILD REVERSAL / LAST SECOND を接続
3. スキップ、再接続、途中 view 更新の収束を実装
4. 既存 result drama / confetti と強度を統合

完了条件:

- 同一チャレンジの演出が一度だけ再生される
- スキップ後は正しい最終合計、勝敗、ライフが表示される
- ローカルとオンラインの見た目・順序が一致する

### D4 — 触覚と調整

1. 触覚設定と対応端末ガード
2. 手番、WILD CALL、COYOTE、ライフ喪失へ限定接続
3. 低性能端末、reduced-motion、画面幅ごとの負荷確認
4. 実プレイで閾値、尺、音量、粒子数を調整

完了条件:

- 初期 OFF、いつでも無効化できる
- 振動の連続発火を抑制できる
- `ひかえめ` でも全状態と勝敗が理解できる

## 9. 検証

### 自動テスト

- HEAT / RALLY / RAISE / レア条件の境界値
- ラウンド変更、COYOTE、再接続によるリセット
- event identity による二重発火防止
- 設定の保存、既定値、非対応 API のフォールバック

### 手動確認

- ローカル 3人 / 4人、オンライン 2タブ、10人モック
- 通常宣言、大幅宣言、特殊能力付き宣言、タイムアウト直前宣言
- COYOTE、PERFECT、CLUTCH、脱落、ゲーム終了
- SFX OFF、触覚 OFF、`prefers-reduced-motion: reduce`
- モバイル縦画面、低性能端末相当、バックグラウンド復帰

各スライスで `npm run typecheck`、`npm test`、`npm run lint`、`npm run build` を行い、演出変更時は実画面も確認する。

## 10. 成功指標

まずは解析基盤を増やさず、プレイテストで評価する。

- 宣言操作の反応が遅い、何が起きたか分からないという指摘がない
- 通常宣言と WILD CALL の強度差を初見で説明できる
- HEAT が上がるほど COYOTE を押す緊張が高まる
- 連戦しても音や振動がうるさく感じず、設定で即座に抑えられる
- 演出 OFF / reduced motion でもゲーム進行と情報理解に欠落がない

## 11. 推奨着手順

**D0 → D1 → D2 → D3 → D4**。

最小リリースは D0 + D1 の `HEAT / RALLY / RAISE`。体験への影響が最も大きい次段として D2 の SFX を入れ、その後に COYOTE シーケンス全体を調整する。
